# OptImageEditor app

Tauri 2 + Svelte 5 + Vite + TypeScript。現在はフェーズ 2-c（結合・統合・ロック）と注釈機能まで実装済み。2-b でレイヤー構造の編集・Undo・PSD 保存。2-a で PSD のレイヤーを読み込んで GPU で合成。フェーズ 1（ビューワー）は完了。1-c でナビゲーター、表示の回転・左右反転、定規、ガイド、グリッド、ピクセルグリッドを追加。676MB の PSD を約 0.19 秒で表示する（詳細は `docs/perf_ipc.md`）。

## 前提（Windows）

| ツール | 確認方法 |
|---|---|
| Node.js 22 以上 | `node -v` |
| Rust（MSVC ツールチェーン） | `rustc -V`、`rustup default` が `stable-x86_64-pc-windows-msvc` |
| Microsoft C++ Build Tools（「C++ によるデスクトップ開発」） | Visual Studio Installer で確認 |
| WebView2 | Windows 11 は標準で搭載 |

## 起動

```powershell
cd D:\google\github\OptImageEditor\app
npm install          # postinstall で patches/ の ag-psd 改修が自動で当たる
npm run tauri dev    # 開発用に起動する
npm run tauri build  # 配布用にビルドする（D:\build-cache\OptImageEditor\release\ に exe、bundle\nsis\ にインストーラ）
```

- ブラウザだけで UI を確認する場合: `npm run dev` を実行して http://localhost:1420 を開く（ファイルパスに関わる機能は無効）
- 型チェック: `npm run check`
- Cargo のビルド生成物は Google ドライブの同期を避けるため `D:\build-cache\OptImageEditor` に出力する（`src-tauri/.cargo/config.toml`。経緯は `docs/build_env.md`）

## 制約（現時点）

- PSD は統合画像だけを表示する。統合画像が無い PSD（PS の「互換性を優先」がオフで保存されたもの）はエラーになる。
- 16 / 32bit の PSD は、表示用に 8bit へ変換する。
- `.svelte.ts` のモジュール名は、同じフォルダの `.svelte` コンポーネントと大文字小文字違いで重ねない（Windows ではファイル名の大文字小文字を区別しないため、`./lib/viewer.svelte` が `Viewer.svelte` に解決されてしまう）。
- 「プログラムから開く」の登録は exe の場所を書き込むので、dev ビルドで登録すると `D:\build-cache\OptImageEditor\debug\optimageeditor.exe` が登録される。配布用ビルドに切り替えたら登録し直す。
- レイヤー合成（2-a）で描画しないもの: レイヤー効果、調整レイヤー、ベクトルマスク、ブレンド条件（Blend If）、ノックアウト。該当レイヤーにはパネルで ⚠ を表示する。16bit / RGB 以外の PSD はレイヤー表示に未対応
- 保存時の統合画像はこのアプリの合成結果。⚠ のある要素（レイヤー効果・調整レイヤーなど）は統合画像に入らない（保存前に 1 回確認する）。レイヤー自体は元のまま保存されるので、PS で開けば正しく表示される。PS で開いて保存し直せば統合画像も PS のものになる
- 保存時に PS の一部の情報（レイヤーの選択状態、レイヤーカンプ等の参照 ID を含むリソース）は書き出さない
- 保存した後は、保存前に削除したレイヤーを Undo で戻せない（新しいファイルに無いため。その手前より古い履歴は保存時に破棄する）
- 結合したレイヤーの画素は GPU 上にあり、Undo 履歴から外れた時点で解放する
- 比較の「並べる」表示中は定規を隠す。差分表示（|A−B|）は未実装
- EXR / HDR は GPU 上で RGBA16F（1 画素 8 バイト）として持つ。32bit float は表示用に 16bit float へ変換する（約 65504 を超える値は無限大になる）。表示はリニア → 露出 → sRGB（トーンマップなし）。deep データの EXR は非対応
- EXR / HDR はデスクトップ版のみ（ブラウザ版はデコーダが無い）
- `[profile.dev.package.exr]` などで EXR の依存クレートも dev ビルドで最適化している（初回の `tauri dev` はビルドが少し長い）
