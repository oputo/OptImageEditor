- 解析日: 2026-10-05
- 解析ツール: `tools/psd_scan.py` と psd-tools 1.23 による個別確認
- 対象: `_tmp/test_text_1.*`、`_tmp/test_alpha_1.*`（PSD / PNG / JPG）。参考として grayObject のパイプラインが書き出した PSD 4 本

## 1. 事実（解析結果）

PSD 内の統合画像と PNG の一致度:

- test_text_1: 完全一致（差分 0）
- test_alpha_1: 不透明な画素と α 値は完全一致。半透明の画素の RGB に平均 0.57 の差があり、α が非常に小さい一部の画素でだけ最大 127 の差がある（見た目への影響なし）
- psd-tools でレイヤーを自前合成した結果も PNG とほぼ一致した（半透明画素の平均差 0.04）

## 2. 推測（要件への含意）

1. **ビューワー**: PSD 内の統合画像を表示すれば PS と同じ見た目になる。難度は低。
2. **レイヤーの合成**: この程度の構成（通常モード、マスク、非表示）なら、自前で合成しても PS とほぼ一致する。
3. **テキストレイヤー**
   - 表示は統合画像で足りる。
   - 編集して「PS で編集可能なテキストレイヤー」のまま保存するのは難度が高い。
   - 現実的な案:
     - (a) 編集していないテキストレイヤーは元のデータをそのまま保存し直す
     - (b) 編集したテキストレイヤーはラスタライズして保存する
     - (c) ag-psd のテキストレイヤー書き込みを試す（PS で開いたときに再描画される仕様と理解しているが、未検証）
   - フォントは PostScript 名（例: `ErasITC-Demi`）から、システムにインストールされたフォントへ対応付ける必要がある。
4. **用途その 1: スクリーンショットへの注釈**（test_text_1）
   - 色付きの矩形枠と短いラベルを描く作業。矩形・矢印・ラベルを置く注釈ツールがあれば、PS を開かずに済む可能性が高い。
5. **用途その 2: 切り抜きの手直し**（test_alpha_1）
   - レイヤーマスクで背景を消している。境界に元の背景色のフリンジが残っている。
   - 必要になりそうな機能: マスクを編集するブラシ、境界の調整（フリンジ除去）、透明付き PNG の書き出し、JPG 書き出し時の背景色の指定。
   - 将来は ComfyUI（BiRefNet）での切り抜きを置き換え候補にできる。
6. **書き出し**: PNG / JPG に sRGB を埋め込むかどうかを選べるとよい。PS の既定動作に合わせるなら、PNG には埋め込む。

## 3. 参考: パイプライン出力の PSD（grayObject の Alarm Clock 4 本）

- 構成は `color`（マスク付き）、`depth`、`mask` の 3 枚で、XMP などの付帯情報がない。PS 以外のツールで書き出されたものと推定。
- これらを正しく読めるかどうかの互換性テストに使える。モデル間の出力を見比べる比較表示（並べて表示、境界線で見比べる表示、グリッド表示、レイヤーの切り替え）の需要あり。

## 描画モードの検証（フェーズ 2-a、2026-10-07、PS 27.10）

`tools/ps_blend_test.jsx` で PS に作らせた検証用 PSD（36 セル）で、このアプリの GPU 合成と PS の統合画像をセルごとに比べた（`tools/blend_test_check.py`）。

- 結果: ディザ合成以外の全セルで差は最大 0〜3（0〜255）。ディザ合成は PS の乱数パターンを再現しないため一致しない。
- PS の計算式について分かったこと（PS の統合画像との比較から推定）:
  - ソフトライトは W3C の式（区間で多項式と平方根を使い分ける式）。平方根だけの式ではない。
  - ビビッドライトは、合成色が 0 / 255 の時を先に判定する（0 → 0、255 → 255）。
  - ハードミックスは `clamp((b + F·s − F) / (1 − F))`。F は塗り（上限 254.5/255）。塗り 100% でも同じ式で、b + s がちょうど 255 の時は背景色の側になる。
  - 「特殊な 8 モード」（焼き込みカラー / リニア、覆い焼きカラー / リニア、ビビッドライト、リニアライト、ハードミックス、差の絶対値）では、塗りは不透明度として効かず、合成色をモードの中立色（焼き込み系は白、覆い焼き系と差の絶対値は黒、ライト系は 50% グレー）へ寄せる。焼き込みカラー、覆い焼き（リニア）、ハードミックスで確認。残りは同じ規則と推定。
  - クリッピングマスクの上のレイヤーは、ベースレイヤーの色を不透明とみなして合成し、その後ベースの不透明度（アルファ）を掛ける。
  - テキストレイヤーはガンマ 1.45 の空間で合成される（PS のカラー設定「テキストカラーのブレンドにガンマを使用 1.45」相当）。
- 実ファイル: 55 レイヤー（スマートオブジェクト中心）の 4096² の PSD で差は最大 1、GPU 合成 88ms。

## PSD 保存で分かったこと（2-b / 2-c、psd_save.rs）

PS 27.10 で開けるかを実機で確認しながら直した点。

- 透明チャンネル（-1）の無いレイヤーレコードを書くと PS が "program error" で開けない（統合した背景で発生）。
  アプリで作るレイヤーは常に -1 チャンネル付きで書き、背景 1 枚だけの文書は PS と同じく「レイヤーレコード無し、
  統合画像 = 背景、3 チャンネル」で書く。
- PS が書くレイヤーレコードは「ブレンド条件」40 バイト（gray + 4 チャンネル × source / dest、すべて 0..255）を持つ。
  アプリで作るレコードにも同じ既定値を書く。
- スマートオブジェクトの中身は全体の追加情報 lnk2（lnkD / lnk3 / lnkE）にまとめて入っており、各項目のキーは
  レイヤーの PlLd の一意 ID（= SoLd の Idnt）。`placed` ではない。
  - SO レイヤーを消した後、使われない lnk2 の項目が残っていると PS が開けなかった（OPT_LG_L1_4096.psd で
    表示レイヤーを結合した時）。保存時に未使用の項目を取り除く（PS も保存時にそうする）。
  - SO を複製したレイヤーは ID を変えてはいけない（中身を共有する。新しい ID にすると中身を引けなくなる）。
- 全体の追加情報ブロックは、長さにパディングを含まず 4 バイト境界に詰める（例: `CAI ` 77 バイト + 3）。
- 生成 AI を使った PSD には `CAI `（コンテンツ認証）と `GenI` ブロックがある。変更せずにコピーして問題なし。
- レイヤー情報の長さは、PS の出力ではいつも 4 の倍数。
