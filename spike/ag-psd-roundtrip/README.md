# Spike: ag-psd による PSD 往復テスト

フェーズ 0（T 案の技術検証）の第 1 弾。

- ライブラリ: ag-psd 31.0.2（Node 22）
- 判定役: psd-tools 1.23
- 実施日: 2026-10-05

## 使い方

```bash
npm install
node roundtrip.mjs <a.psd> [b.psd ...]   # 無変更で読み書き → out/<name>.rt.psd
node edit_test.mjs <a.psd>               # テキスト変更 + レイヤー非表示 → out/<name>.edit.psd
python compare.py <orig.psd> out/<name>.rt.psd   # 差分レポート（pip install psd-tools）
```

## 結果（既存サンプル 3 本）

対象: `_tmp/test_text_1.psd`、`_tmp/test_alpha_1.psd`、grayObject の `Alarm Clock Mage-Flow.psd`

### 問題なかったもの（事実）

| 項目 | 結果 |
|---|---|
| ヘッダー（サイズ / モード / チャンネル数） | 一致 |
| レイヤー数・名前・種類・描画モード・不透明度・表示状態・クリッピング・位置 | すべて一致 |
| レイヤーの画素、レイヤーマスク | 完全一致 |
| 統合画像（不透明な文書） | 完全一致 |
| 統合画像（透明のある文書） | α は完全一致。半透明の画素の RGB にだけ差がある（最大 42、平均 0.006）。見た目への影響はほぼない |
| テキストの文字列 | 一致。FontSet の並び順が変わり、未使用の MyriadPro-Regular が消えた。ただし参照先のフォント名は同じ（ErasITC-Demi） |
| 速度 | 2884×1516 / 6 レイヤーで、読み込み 140ms、書き込み 190ms（クラウド環境の Node） |

### 失われたもの（事実）

| 種類 | 失われたデータ | 影響（推測） |
|---|---|---|
| 文書全体の付加情報 | `CAI `（コンテンツクレデンシャル）、`GenI`（生成 AI 関連の情報）、`OCIO`（OCIO カラー設定）、`Patt`（パターン。今回は空） | 今回は小さい。ただし **ag-psd は未知のブロックを保持せずに捨てる**ことが分かった。パターン塗りやパターンオーバーレイを使う PSD では、`Patt` が消えると壊れる可能性がある |
| イメージリソース | 1028（IPTC）、1058（EXIF）、1036（サムネイル。今回は生成を無効にしたため）、印刷関連（1013 / 1016 / 1083 / 10000 ほか）、1077（DisplayInfo） | 撮影情報・メタデータ・印刷設定が消える。編集作業そのものには影響しない |

### 編集テスト（`edit_test.mjs`）

テキスト `<A>` を `<A> edited by ag-psd` に変更し、`Layer 1` を非表示にして書き出した。`invalidateTextLayers: true` を指定。

- psd-tools で読み直すと、テキストの変更と非表示は反映されていた。
- 統合画像は **再生成されない**（ag-psd の仕様）。統合画像だけを見るビューワーでは、古い見た目のまま表示される。
  → アプリ側で、保存時に統合画像を自前で合成して書き込む必要がある。

## 要確認（Photoshop 27.10 での確認をオーナーに依頼）

`_tmp/roundtrip/` に書き出したファイルを PS で開き、次の点を確認する。

1. `*.rt.psd` がエラーなく開け、元のファイルと見た目もレイヤー構成も同じか
2. `test_text_1.rt.psd` のテキストレイヤーを、そのまま編集できるか（フォントが ErasITC-Demi のままか）
3. `test_text_1.edit.psd` を開いたとき、`<A>` の文字が新しい文字列で再描画されるか。警告が出るかどうか

### PS 27.10 での確認結果（2026-10-05、オーナーが確認）

| 確認項目 | 結果 |
|---|---|
| 1. `*.rt.psd` が開け、元と同じか | OK |
| 2. `test_text_1.rt.psd` のテキストをそのまま編集できるか | OK |
| 3. `test_text_1.edit.psd` を開いたとき | 開いた時点で「Some text layers might need to be updated before they can be used for vector based output. Do you want to update these layers now?」という確認が出る。ダイアログの背後では `<A>` が古い描画のまま。`Layer 1` の非表示は反映されている。解像度（168ppi）とフォント（Eras Demi ITC / 60px）は保持されている |

- 3 の確認は、`invalidateTextLayers` を指定したときの想定どおりの挙動（PS に再描画を依頼する印）。
- 「Update」を押すと `<A>` が「<A> edited by ag-psd」で再描画され、編集可能なテキストレイヤーとして保持されることを確認した（2026-10-05、オーナーが確認）。
- → アプリでテキストを編集した場合の保存方式として、**A 案（再描画の印を付けて保存し、PS 側で描き直してもらう）が成立する**。PS で開いたときにダイアログが 1 回出ることだけが代償になる。

## 暫定的な評価（推測を含む）

- 単純な構成の PSD なら、ag-psd で十分に往復できる。
- 対策が必要な点:
  1. **未知のブロックを保持すること**: ag-psd を改修し、読めないブロックは元のバイナリのまま保持して書き戻す。これができないと、PS の新しい機能のデータが黙って消える。
  2. **統合画像の再生成**: 保存時にアプリ側で合成した統合画像を書き込む。
  3. **メタデータの保持**: EXIF / IPTC などのイメージリソースを、元のバイナリのまま書き戻す。
- 調整レイヤー、スマートオブジェクト、レイヤー効果を含む PSD での検証はまだ。実案件に近いサンプルが届いたら、同じスクリプトで続けて検証する。
